## 0.2.7：Codex 并行翻译与耗时记录

Codex 默认同时翻译 2 批，可在设置中调整“同时翻译批次数”为 1–4。1 表示逐批处理；遇到请求限制或网络不稳定时可改回 1。此选项控制重叠等待，仍使用每批独立的官方 CLI 临时调用，不复用聊天历史或后台进程。并行不减少论文需要翻译的内容，不保证按倍数提速，也不保证消耗更少订阅额度。有效缓存继续复用。

“每秒请求数”只用于 API，切到 Codex 时禁用并提示使用并行批次数。完成后显示本次用时与实际模型调用次数；资源准备、引擎运行、各调用耗时和 CLI 返回的 token 数字记录在报告中。各调用时间之和可因并行而大于总用时；CLI token 统计不能直接换算为周额度百分比。插件不记录提示词、译文、密钥或登录令牌到这份性能报告。最新成功保存任务的统计保留在 Zotero 配置目录的 `babeldoc-local/last-translation-performance.json`，任务清理后仍可诊断；任务目录内仍写入 `translation-report.json`。

## 0.2.6：每篇论文单独选择翻译页码

点击“翻译”后，在本次任务窗口填写页码，例如 `3-8` 或 `1-5,8`；留空翻译全文，点击“开始翻译”后才启动任务。页码不再放在统一设置中，也不会沿用上一篇论文的范围。旧版本保存的页码自动忽略。关闭或取消页码窗口不会启动翻译。

## 0.2.5：修复 Windows 长路径导致的附件导入失败

论文标题较长时，生成的 PDF 完整任务路径可能超过 Windows 旧式文件接口的 260 字符限制。文件实际存在，但 Zotero 的读取和附件复制代码仍可能报 `NS_ERROR_FILE_NOT_FOUND`。新版在把路径交给 Zotero 之前，由 Python 校验输出，并将生成文件规范为同一任务目录内的 `export/translated.pdf`、`export/bilingual.pdf`。两份副本均验证完成后才移除原来的生成文件名。附件显示标题及检查备注保持原有规则，不影响原论文 PDF。

这是保存附件阶段的错误，提示保留目录时不需要重新翻译。可将该目录中已有的两份 PDF 复制到较短目录，再添加为原条目的子附件。导入失败时仍会保留生成文件，方便恢复。

## 0.2.4：个别段落失败也保存 PDF，未译处保留原文

个别空译文、截断输出或调用失败，不再导致后续整篇请求被拦截，也不再丢弃已经生成的 PDF。翻译失败处由 BabelDOC 保留原文，其他有效译文继续使用。批量响应中有空段时，保留有效段落，由 BabelDOC 的逐段回退处理空段。空译文和含空段的批量响应不会作为成功译文写入缓存。

译文和双语 PDF 仍会保存为原条目的子附件。附件标题标明“含未译原文”或“需检查”，标签和附件备注记录检测到的未译段落数、原文页码及错误类别。PDF 用批注提示相关页面，不改变正文排版。未译统计来自 BabelDOC 跟踪记录，不能保证自动识别所有语义遗漏。

额度、认证或模型权限错误会暂停后续远程调用；连续三次连接、超时或无法分类的调用失败也会暂停。仍可复用已有缓存，其余未译段落保留原文并输出部分译文，不自动回退到付费 API。Codex 中途报告重连、但最终成功返回有效译文时，使用最终结果。进度中增加已完成的模型调用次数和当前等待时间。

只有真正无法生成 PDF 或文件导入失败，才不能正常添加附件；已生成的 PDF 会保留，并显示恢复目录。错误弹窗在任务解锁后显示。安装更新并重启 Zotero 后生效，已运行的任务仍使用旧代码。重译会复用有效缓存，但重试缺失内容仍可能消耗模型额度。

## 0.2.3：从当前 Codex 模型列表直接选择

选择“Codex 登录账户”后，插件会从本机官方 Codex CLI 及其当前 ChatGPT 登录读取模型列表，直接点击模型卡片选择，无需手动填写模型名。切换账户或更新 CLI 后，可以点击“刷新模型列表”。模型列表没有写死，以当前 CLI 返回的目录为准；实际翻译时仍可能受到服务可用性变化的影响。

推理强度仅显示所选模型支持的选项。原强度不受支持时，优先切换到 low，否则使用模型返回的默认强度。首次配置预选目录中的默认模型；已保存的模型不在列表里时，会要求重新选择。模型和强度都在点击“保存设置”后生效；修改 Codex 桌面端的选择不会自动修改插件设置。

列表通过官方 [app-server 的 `model/list` 接口](https://learn.chatgpt.com/docs/app-server)读取，不发起聊天或翻译调用。读取失败时，请完成 ChatGPT 登录、检查网络及 CLI 版本后刷新；不会回退到手动输入或内置模型名单。原有 API 方式、地址、模型名和密钥继续保留。

针对论文翻译，建议先从以下配置试起：

| 需求 | 模型 | 推理强度 |
| --- | --- | --- |
| 重视技术术语、表达与忠实度的起点 | `gpt-6.1-sol` | `low` |
| 更重视速度和节省额度 | `gpt-6-luna` | `low` |
| 难句较多，低强度测试中理解不佳 | `gpt-6.1-sol` | `medium` |

这是针对本翻译工作流的建议，不是已完成的模型翻译质量排名。先用同样的两页对比术语、遗漏、公式标记和句意，再决定是否提高强度。更高强度通常增加耗时和推理用量，不能修复 PDF 背景遮字或版面错误；日常整篇翻译不建议一开始就用 xhigh 或 max。

可用模型和强度取决于账户、CLI 与服务端。更换模型或提高强度后，相关翻译可能需要重新调用以避免复用不同设置的缓存；原有 low 缓存保持兼容。翻译仍使用 Codex 账户额度，不会回退到 API。

参考：[官方模型说明](https://learn.chatgpt.com/docs/models)、[官方模型与推理强度选择](https://developers.openai.com/api/docs/guides/deployment-checklist)。

## 0.2.0：保留 API，新增 Codex 登录翻译

“翻译方式”可选择原有 API/本机模型接口，或“Codex 已登录的 ChatGPT 账户”。切换不会删除原 API 地址、模型名或已保存的密钥，不会自动在两个后端之间回退。

使用 Codex：

1. 安装官方 Codex CLI（已安装可跳过）：`npm install -g @openai/codex`。
2. 在插件设置中选择“Codex 登录账户”。Codex 路径留空会自动查找；也可填写原生 `codex.exe` 完整路径。
3. 点击“登录 Codex（官方浏览器）”并亲自在官方浏览器页面完成 ChatGPT 账户登录。已经登录时，直接点“检查 Codex 登录”。也可自行运行 `codex login`。
4. 在加载出的列表中点选模型及其支持的推理强度，再保存设置、翻译论文。必要时点击“刷新模型列表”。无需填写 OpenAI API Key。插件会检查登录方式，只接受 ChatGPT 账户登录，拒绝 API Key 登录。

后台调用使用官方 `codex exec --ephemeral`：不创建持久化的本地聊天会话，提示词和返回文本通过管道传递。临时调用**仍会消耗 Codex 账户额度**，不是免费或无限调用；长论文可能消耗较多额度。不保存本地会话也**不等于 OpenAI 服务端零留存**。正文仍会发送给 OpenAI，适用账户和工作区的数据政策。

Codex 模式默认同时处理 2 批（可调 1–4），并关闭自动术语提取以减少额外调用。额度用尽、登录失败、网络超时或模型无权限时会停止，不会偷偷回退到付费 API。插件不读取、复制或导出 Codex 登录令牌。Codex 进程会在取消任务时一起结束；Windows 已做本机验证，其他平台尚未实机验证。

原有 API 方式继续保留。DeepSeek 官方接口翻译时会关闭推理模式，并将译文输出上限调整为 8192 tokens；上限不是每次都会用满的固定消耗。其他兼容接口不额外发送 DeepSeek 专用参数。

### 空段与色块遮字修复

旧版可能将模型返回的空字符串缓存并当作成功译文，导致整段空白。0.2.4 跳过无效缓存，失败处保留原文，将两份 PDF 正常保存并附上检查标记和页面批注，替代之前的整篇拦截逻辑。有效的同后端缓存仍可复用。

对文字行附近的浅色背景图形，新版调整绘制顺序，先绘制背景、再绘制文字，减少高亮色块盖住译文的问题。这是针对已复现问题的修复，不能保证所有复杂 PDF 的排版与语义翻译都完全正确。

**已有的缺段 PDF 不会自动修好，需要重新翻译。** 可先指定问题页做小范围验证，再翻译全文。新版不会自动为旧任务追加模型请求、扣费或覆盖原 PDF。

参考：[官方 Codex 临时调用](https://learn.chatgpt.com/docs/non-interactive-mode)、[官方登录说明](https://learn.chatgpt.com/docs/auth)。

## 数据如何处理

- PDF 解析、版面分析、排版和 PDF 生成均在本机 Python 进程中完成，不使用 BabelDOC 的在线翻译服务器。
- 文本翻译使用你设置的兼容 OpenAI Chat Completions 接口。配置云端服务时，待翻译文本会发送到该服务；配置本机模型时，文本也由本机处理。模型服务本身的联网行为取决于它的配置。
- 首次运行通常需要联网下载 BabelDOC 的版面模型、字体等资源。资源准备好且模型位于本机时，可以离线使用。BabelDOC 的翻译缓存、模型和字体缓存由 BabelDOC 管理，插件不清理这些缓存。
- 默认地址为 `http://127.0.0.1:11434/v1`，模型名需自行填写。插件不捆绑、不安装大语言模型，也不代为购买 API。
- API 密钥保存在 Zotero 密码管理器，按接口地址区分；通过标准输入交给 Python，不出现在进程参数、普通设置文件和插件日志中。
- 新附件使用 Zotero 标准导入 API，按照 Zotero 自身的文件同步设置同步。原 PDF 不被修改。

## 为什么首次运行要下载版面模型和字体？

BabelDOC 需要本地资源来识别 PDF 结构，并将译文重新排成可阅读的 PDF。这些资源与负责文字翻译的大语言模型不同。

| 资源 | 用途 | 是否负责翻译文字 |
| --- | --- | --- |
| 版面分析模型 | 识别正文、标题、公式、图表等区域的位置，帮助保留论文排版 | 否 |
| 字体库 | 提供中文等译文所需的字形，减少方框、缺字和乱码 | 否 |
| 字符映射（CMap） | 帮助读取 PDF 内部的文字编码 | 否 |
| 分词器缓存 | 支持引擎内部的文本分词和长度处理 | 否 |

**换一篇论文，不需要重新下载一套模型和字体。** 不同论文共用这些资源；BabelDOC 会用同一个通用版面模型分别分析每篇论文，并根据译文语言和样式选用字体。它不会为每篇论文重新训练或下载一个专用模型。

通常首次联网下载一次后就会复用本地缓存。只有缓存被清理、文件损坏，或升级后需要新资源时，才会补下载。取消任务或关闭 Zotero 不会清理这些资源。BabelDOC 0.6.4 在本次验证中准备了 182 个资源，约 336 MB；这个体积不包含 Python 环境或翻译大语言模型，其他版本可能不同。

默认缓存目录是当前系统用户主目录下的 `.cache/babeldoc`。Windows 示例：`C:\Users\你的用户名\.cache\babeldoc`。缓存包含 `models`、`fonts`、`cmap` 和 `tiktoken` 等子目录，不是每篇论文的专属附件目录。

### 为什么会一直显示“加载”？

首次准备会下载覆盖多种语言的字体，并校验模型和其他资源，所需时间受网络和代理影响。旧版在这一步尚未收到论文翻译进度，因此可能一直显示 0%，即使后台仍在下载。

0.1.1 起会显示资源数量、缓存体积和耗时，并提供独立的“准备资源”按钮。如果准备失败或超过 10 分钟，请检查网络/代理后重试；已缓存的完整资源会复用，不会全部重下。资源进度到 100% 表示这一阶段完成，之后才进入论文解析和文字翻译。

### 使用 DeepSeek 时，哪些在本地？

例如将模型接口配置为 DeepSeek 云端服务时，PDF 解析、版面分析和排版仍在本机完成，待翻译文本会发送给 DeepSeek。下载本地版面模型和字体不会使云端翻译变成本地翻译，也不会经过 BabelDOC 的在线翻译服务器。希望离线处理时，需要另外运行本机翻译模型，并先准备好上述资源。

## 安装

支持 Zotero 7–10；当前在 Windows Zotero 10.0.6 上验证。Python 3.10–3.13，推荐 3.12。macOS/Linux 提供安装脚本，尚未在这两种系统上实机验证。

1. 解压 `zotero-babeldoc-0.2.7-install.zip`。
2. Zotero → 工具 → 插件 → 齿轮 → 从文件安装插件，选择 `zotero-babeldoc-0.2.7.xpi`。
3. 安装本地 BabelDOC 环境。

Windows PowerShell，在解压目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
# 可选：同时预下载模型和字体
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Warmup
```

macOS / Linux：

```sh
sh scripts/setup.sh
# 可选：同时预下载资源
sh scripts/setup.sh --warmup
```

脚本创建独立 `.venv`，安装 `BabelDOC==0.6.4`，不修改系统 Python 包。Linux 需要系统提供 Python venv 支持。安装路径应保留在固定位置，移动或删除环境后需要重新填写 Python 路径。首次安装和下载模型需要可访问软件源及 BabelDOC 资源源。

4. Zotero → 工具 → BabelDOC · 论文翻译 → 设置与任务进度。填写脚本输出的 Python 路径、接口地址、模型名，必要时填写 API 密钥，点击“保存设置”和“检查环境”。“检查环境”检查 Python/BabelDOC 导入，不调用模型，不保证模型端点可用。

首次使用时也可先点击“准备资源”。此操作仅下载和校验本机版面分析模型、字体、字符映射等资源，不发送论文或调用翻译 API。字体库覆盖多种语言，不是每篇论文下载一套。准备成功后后续论文复用缓存；只有资源缺失、损坏或升级时才补下载。下载和校验期间会显示已缓存文件数、体积和耗时；换阶段时进度条会重新开始计算该阶段的进度。

### 本机模型

先在本机模型服务中下载并运行一个支持翻译、上下文足够且遵循指令的模型，然后填写实际模型名。Ollama 等提供兼容接口的服务可填写 `http://127.0.0.1:11434/v1`；密钥留空即可。BabelDOC 使用多段结构化提示与公式标记，较小模型可能无法保持格式，质量取决于所选模型。不要把“安装 BabelDOC”理解成已安装翻译大语言模型。

### 云端模型

填写服务商给出的兼容 OpenAI 接口地址（通常以 `/v1` 结尾）、模型名和密钥，文本将发送给该服务。插件不会自动回退到其他服务。

## 使用

1. 在文库中选中**一篇论文**或该论文下的**一个 PDF**，或在 Zotero 主窗口中打开该 PDF 阅读标签。
2. 工具 → BabelDOC → 翻译当前论文，或者在文库右键菜单选择“BabelDOC：翻译 PDF 并添加双语附件”。
3. 在弹出的翻译窗口填写本次页码，留空翻译全文，再点击“开始翻译”。
4. 在设置与任务进度窗口查看进度、取消任务。关闭窗口不会停止任务，可通过工具菜单再次打开。
5. 完成后，原文献条目下新增 `译文 · zh · BabelDOC` 和 `双语对照 · zh · BabelDOC` 两个附件。

选中文献条目时，插件忽略已生成的 BabelDOC 附件；有多个原文 PDF 时让你选择。只处理本机存在的 PDF，附件尚未下载时会提示。独立 PDF 请先添加到文献条目下。每次翻译保留一对新附件，不覆盖已有翻译。

任务绑定启动时的条目和附件，切换论文不改变保存位置。为避免重复任务，一次只翻译一篇论文。导入阶段会禁用取消按钮，保证两个附件成对保存。若第二个附件导入失败，撤销此次已添加的附件；生成的 PDF 会保留在提示的任务目录，便于手动恢复。翻译完成或取消后清理本次临时文件。

页码在每次点击翻译后的窗口填写，按 PDF 文件实际页序从 1 开始（含封面），范围包含首尾页；可填写 `1-5,8`，留空翻译全文。每次任务独立选择，不保存到统一设置。只翻译指定页时，其余页的保留行为沿用 BabelDOC 默认行为。扫描件、加密 PDF 或复杂排版可能失败，插件会显示 BabelDOC 的错误信息。

## 开发

```powershell
npm test
npm run build
```

源码无 npm 依赖。`addon/` 是 XPI 内容，`worker.py` 使用 BabelDOC 的 Python 异步流式 API。`scripts/build.py` 生成 XPI、源码包、安装包与校验文件。测试说明见 [TESTING.md](TESTING.md)。测试不会调用付费模型，也不会访问真实个人文库。

参考：[BabelDOC 源码和接口](https://github.com/funstory-ai/BabelDOC)、[Zotero 插件开发文档](https://www.zotero.org/support/dev/zotero_7_for_developers)。插件包装代码采用 MIT；BabelDOC 是单独安装的 AGPL-3.0 项目，其代码不包含在 XPI 中，其许可见上游项目。
